开始前先明确Before you start

刷入过程不碰固件、不写分区、不解 bootloader。原理是设备「关于设备」页有个隐藏入口，触发后它向厂商接口发一个 adbAdmit 请求；我们在 Mac 本地把这个请求截下来自己回一个成功响应，设备就重建 USB gadget 打开 ADB。之后所有改动都通过 ADB 的 root shell 完成，根文件系统全程保持只读。

Nothing here touches the firmware, writes a partition, or unlocks a bootloader. The device's "About device" screen has a hidden entry point; triggering it makes the device send one adbAdmit request to the vendor API. We intercept exactly that request on the Mac and answer it ourselves, and the device rebuilds its USB gadget with ADB exposed. Everything after that happens over a root ADB shell, with the root filesystem read-only throughout.

prebuilt/ holds MIPS binaries already cross-compiled and ABI-verified, so you don't need Docker.

Terminal · macOS
brew install --cask android-platform-tools

git clone https://github.com/theBillLee/C1ancher-mac.git
cd C1ancher-mac
chmod +x macos/*.sh

macOS 不需要装任何 ADB 驱动，设备的 VID_18D1 会直接枚举。准备一根支持数据传输的 USB-C 线 —— 充电线是 adb devices 返回空最常见的原因。

macOS needs no ADB driver — the device's VID_18D1 enumerates directly. Have a data-capable USB-C cable ready; a charge-only cable is the most common reason adb devices comes back empty.

01

开互联网共享Turn on Internet Sharing

设备必须连这台 Mac 发出的热点，不能连家里路由器 —— 整个方案依赖流量经过 Mac。

The device must join a hotspot this Mac creates. The method depends on its traffic passing through the Mac, so a device still on your home router will never trigger.

系统设置 → 通用 → 共享 → 互联网共享，共享来源选你的上网接口，「用以下端口共享给电脑」勾 Wi-Fi，在「Wi-Fi 选项」里设好名称和 WPA2 密码，然后打开开关。

System Settings → General → Sharing → Internet Sharing. Share from your uplink interface, to Wi-Fi. Set a name and WPA2 password under "Wi-Fi Options", then switch it on.

M 系 Mac 的坑：单张网卡同时「连 Wi-Fi 上网」+「发 Wi-Fi 热点」经常起不来或不稳。最稳的组合是上网走 USB-C 转以太网，共享给 Wi-Fi。
Apple Silicon caveat: one radio doing "join Wi-Fi uplink" and "serve Wi-Fi hotspot" at once is often unstable or refuses to start. The reliable combination is uplink over USB-C Ethernet, shared to Wi-Fi.

打开后 Mac 会出现 bridge100，网关通常是 192.168.2.1。然后在 C1-Slim 上连接这个热点。

The Mac gains a bridge100 interface, usually at 192.168.2.1. Connect the C1-Slim to that hotspot.

02

自检，顺便找到设备 MACPreflight, and find your device MAC

自检脚本只读，不改任何东西。它逐项检查环境，并列出热点上的所有客户端 —— 你的设备 MAC 就在这份列表里。脚本里的默认 MAC 是原作者那台机器的，不是你的。

The preflight script is read-only. It checks every prerequisite and lists the clients on your hotspot — that's how you find your device's MAC. The default MAC in the scripts belongs to the original author's unit, not yours.

Terminal · macOS
./macos/doctor.sh

认不出哪个是 C1-Slim？把设备 Wi-Fi 关掉再跑一次，消失的那行就是它。记下这个 MAC。

Can't tell which client is the C1-Slim? Turn its Wi-Fi off, run again, and note the row that disappeared.

临时打开 ADBOpen ADB temporarily

把上一步的 MAC 填进去运行。脚本会在 pf 里加一条只针对「这台设备 → 厂商接口 443」的重定向规则，其余流量不受影响。

Run it with the MAC from the previous step. The script loads one pf rule scoped to "this device → the vendor API on 443"; nothing else is touched.

sudo python3 macos/c1-adb-admit-macos.py \
    --device-mac 58:C5:87:XX:XX:XX

等到这三行出现，看到 READY 之前不要碰设备：

Wait for all three lines. Do not touch the device before READY:

预期输出Expected output

PF_RULE_LOADED anchor=com.apple/c1slim-adb ...
READY open About-device and press Enter 10 times

然后在设备上触发隐藏入口Then trigger the hidden entry point

  1. 打开设备的「关于设备」
  2. 把焦点停在显示静态版本信息的那一项上
  3. 约 5 秒内，快速按下并完整松开全键盘 Enter 共 10 次
  1. Open About device
  2. Put the focus on the item showing static version information
  3. Within about 5 seconds, press and fully release the keyboard Enter 10 times
固件按松开事件计数，所以每次必须完整按下再松开，而且不能太慢。
不要执行 C → S → Enter —— 那个组合进的是 GCTest，和 ADB 无关。
The firmware counts release events, so each press must complete, and don't go slowly.
Do not use C → S → Enter — that opens GCTest, which is unrelated.

成功后日志会出现 TLS_OK 和 APPROVED，设备重建 USB gadget，Mac 上会看到一次 USB 断开重连。插上 USB 验证：

On success the log shows TLS_OK then APPROVED, the device rebuilds its USB gadget, and macOS registers a USB disconnect/reconnect. Plug in USB and verify:

Terminal · macOS
adb kill-server && adb start-server
adb devices -l          # MagicPen-xxxxxx  device
adb shell id            # uid=0(root) gid=0(root)
这个 ADB 只在当前开机周期有效，重启就没了 —— 第 05 步才让它常驻。
This ADB session lasts only for the current boot. Step 05 makes it persistent.
04

整机备份Back up the device

别跳过这一步Do not skip this

新机器手上没有原厂系统镜像。这一步导出的东西是你唯一的救砖资本 —— 后面任何一步出问题，恢复都要靠它。

A new unit ships with no system image in your hands. What this exports is your only way back if anything later goes wrong.

备份脚本全程只读，导出分区表、启动脚本和各分区镜像，并生成校验和。默认只备份 512 MB 以下的分区。

The backup script is read-only throughout. It exports the partition table, boot scripts and partition images with a checksum manifest. By default it takes partitions under 512 MB.

Terminal · macOS
./macos/backup.sh

# every partition, no size limit:
./macos/backup.sh --all

结果写到 ~/C1Slim-Backup/<时间戳>/。把这个目录复制到另一块盘再继续。

Results land in ~/C1Slim-Backup/<timestamp>/. Copy that directory to another disk before continuing.

Terminal · macOS
cd ~/C1Slim-Backup/<timestamp> && shasum -a 256 -c SHA256SUMS
05

让 ADB 开机常驻Make ADB survive reboot

原厂 /etc/init.d/S90usb 里本来就有一行 ADB FunctionFS 启动项，只是被注释掉了。这一步把它取消注释。

The stock /etc/init.d/S90usb already contains an ADB FunctionFS startup line — it is merely commented out. This uncomments it.

Terminal · macOS
./macos/install-open-adb.sh install --reboot

脚本从设备 adb pull 出原始文件，比对已知哈希 c2b278b2… 后才做那一行修改，写入前后都做校验，失败自动回滚并把根分区重挂为只读。原文件保留在设备的三个位置。

The stock file is pulled from the device and checked against the known hash c2b278b2… before the single-line edit is applied. The installer verifies before and after writing, and on failure restores the original and remounts / read-only. Copies are kept in three locations on the device.

安全边界Security boundary

装完之后任何电脑插上 USB 都直接是 root shell，没有 adb_keys 授权。这是上游项目明确选择的开放开发模式，不是疏漏。介意的话到此为止，别做下一步。

After this, any computer that plugs in gets a root shell — no adb_keys, no authorization prompt. That is a deliberate choice by the upstream project, not an oversight. If it bothers you, stop here.

06

安装 C1ancherInstall C1ancher

部署主程序、app_daemon supervisor、Neofetch，并为这台设备生成独有的 Ed25519 SSH host key。

Deploys the application, the app_daemon supervisor, Neofetch, and generates a unique Ed25519 SSH host key for the device.

Terminal · macOS
./macos/install-default-app.sh install --reboot

设备端脚本逐文件校验 SHA-256，失败自动回滚。--reboot 会重启并验证冷启动后确实是 C1ancher 起来，而且 app_daemon 和 C1ancher 各只有一个实例。

The device-side script verifies every file by SHA-256 and rolls back on failure. --reboot confirms that C1ancher is what comes up from cold, with exactly one instance each of it and app_daemon.

到这里就完成了That's it

设备现在是 C1ancher 的 3×3 九宫格首页：上 WI-FI、左 SSH、右 TERMINAL、下 DEVICE（自动跑 neofetch），四角显示 Wi-Fi 状态、SSH 状态、电量和时间。原厂软件仍在磁盘上，没有被删。

You now have the C1ancher 3×3 home screen: WI-FI up, SSH left, TERMINAL right, DEVICE down (runs neofetch). Corners show Wi-Fi state, SSH state, battery and time. The stock software is still on disk.

07

删除原厂软件 · 可选Remove the stock software · optional

不可逆Irreversible

这一步删掉 /usr/bin/d261。设备端没有恢复路径，只能靠第 04 步备份出来的镜像。

This deletes /usr/bin/d261. There is no on-device recovery path — only the images from step 04.

确认备份完好、shasum -c 全部通过、而且已经复制到另一块盘之后，再考虑跑它。不做这步完全不影响使用。

Only consider it once your backup passes shasum -c and lives on a second disk. Skipping it costs you nothing functionally.

Terminal · macOS
./macos/install-default-app.sh remove-original --reboot

日志隐私：macos/adb-admit-plaintext.log 记录 TLS 解密后的完整 HTTP 请求，可能包含 Cookie、手机号、sessionId、penId 和设备序列号。排错求助前先删掉这些字段，用完删掉日志。

Log privacy: macos/adb-admit-plaintext.log records the full decrypted HTTP request and can contain cookies, a phone number, sessionId, penId and the device serial. Strip those before sharing it, and delete the log when you're done.

Upstream: fwz233-RE/C1ancher (GPL-3.0). Use only on hardware you own. Once you have a root shell, prioritise read-only backup — don't remount writable, write eMMC or edit boot scripts before you have a proven unbrick path.
